Micronaut JSON Schema can also discover JSON Schema definitions directly from Oracle metadata and generate Java records from the discovered schemas.

The current Oracle discovery pipeline supports:

* Oracle SQL domains that declare JSON validation rules
* Oracle JSON Relational Duality Views

This flow is available through the dedicated Gradle and Maven plugins included in this project.

Built-in Oracle discovery providers are configured by class name:

* `io.micronaut.jsonschema.generator.oracle.OracleDomainDiscoveryProvider`
* `io.micronaut.jsonschema.generator.oracle.OracleDualityJsonViewDiscoveryProvider`

Each configured source declares:

* `name`
* `providerClassName`
* optional `owner`
* provider-specific `options`

== Gradle

Apply the plugin and configure the target package plus one or more discovery sources:

[source,groovy]
----
plugins {
    id "io.micronaut.jsonschema.oracle"
}

oracleJsonSchema {
    targetPackage = "example.oracle.generated"
    sources = [
        [
            name: "domains",
            providerClassName: "io.micronaut.jsonschema.generator.oracle.OracleDomainDiscoveryProvider",
            owner: "APP",
            options: [
                include: "APP_JSON"
            ]
        ],
        [
            name: "views",
            providerClassName: "io.micronaut.jsonschema.generator.oracle.OracleDualityJsonViewDiscoveryProvider",
            owner: "APP",
            options: [
                include: "APP_VIEW"
            ]
        ]
    ]
}
----

If the Oracle JDBC driver is not already visible to the task, provide it through `jdbcClasspath`.

[source,groovy]
----
configurations {
    oracleJsonSchemaJdbc
}

dependencies {
    oracleJsonSchemaJdbc "com.oracle.database.jdbc:ojdbc11:<version>"
}

oracleJsonSchema {
    jdbcClasspath.from(configurations.oracleJsonSchemaJdbc)
}
----

Custom discovery providers can be added through the dedicated `oracleJsonSchemaProviders` configuration:

[source,groovy]
----
dependencies {
    oracleJsonSchemaProviders project(":oracle-schema-providers")
}

oracleJsonSchema {
    sources = [
        [
            name: "legacy",
            providerClassName: "example.oracle.LegacySchemaDiscoveryProvider",
            options: [
                tablePattern: "LEGACY_%"
            ]
        ]
    ]
}
----

Custom providers are selected by `providerClassName`, but they must also be registered through Java `ServiceLoader`:

[source]
----
META-INF/services/io.micronaut.jsonschema.generator.oracle.OracleSchemaDiscoveryProvider
----

For example:

[source]
----
example.oracle.LegacySchemaDiscoveryProvider
----

`providerClassName` must exactly match the implementation class name listed in that service file. The provider jar must be present on `oracleJsonSchemaProviders`, and the implementation must expose a public no-argument constructor. This keeps custom providers compatible with GraalVM native image builds without requiring reflective construction.

The built-in providers currently support these source options:

[cols="2,3", options="header"]
|===
| Provider class
| Supported options

| `io.micronaut.jsonschema.generator.oracle.OracleDomainDiscoveryProvider`
| `include`, `exclude`, `prefix`

| `io.micronaut.jsonschema.generator.oracle.OracleDualityJsonViewDiscoveryProvider`
| `include`, `exclude`
|===

For the built-in providers, `include` and `exclude` match discovered Oracle object names by exact name first and also by Oracle-style uppercase normalization. The domain provider also supports `prefix` to constrain discovered domain names by prefix. This keeps normal unquoted identifiers working as expected while still allowing exact matching for quoted mixed-case names.

=== Gradle credentials

The Gradle plugin can resolve connection settings from explicit extension values, Gradle properties, or environment variables.

[cols="2,2", options="header"]
|===
| Value | Supported names
| JDBC URL
| `oracleJsonSchema.jdbcUrl`, `ORACLE_JSON_SCHEMA_JDBC_URL`
| Username
| `oracleJsonSchema.username`, `ORACLE_JSON_SCHEMA_USERNAME`
| Password
| `oracleJsonSchema.password`, `ORACLE_JSON_SCHEMA_PASSWORD`
|===

This lets projects keep secrets outside `build.gradle`, for example in `~/.gradle/gradle.properties`:

[source,properties]
----
oracleJsonSchema.jdbcUrl=jdbc:oracle:thin:@localhost:1521/FREEPDB1
oracleJsonSchema.username=app
oracleJsonSchema.password=secret
----

== Maven

The Maven plugin can be configured in the build like any other mojo:

[source,xml]
----
<plugin>
  <groupId>io.micronaut.jsonschema</groupId>
  <artifactId>micronaut-json-schema-maven-plugin</artifactId>
  <executions>
    <execution>
      <goals>
        <goal>generate-from-oracle-json-schema</goal>
      </goals>
    </execution>
  </executions>
  <configuration>
    <skip>false</skip>
    <jdbcUrl>${oracleJsonSchema.jdbcUrl}</jdbcUrl>
    <targetPackage>example.oracle.generated</targetPackage>
    <sources>
      <source>
        <name>domains</name>
        <providerClassName>io.micronaut.jsonschema.generator.oracle.OracleDomainDiscoveryProvider</providerClassName>
        <owner>APP</owner>
        <options>
          <include>APP_JSON</include>
        </options>
      </source>
      <source>
        <name>views</name>
        <providerClassName>io.micronaut.jsonschema.generator.oracle.OracleDualityJsonViewDiscoveryProvider</providerClassName>
        <owner>APP</owner>
        <options>
          <include>APP_VIEW</include>
        </options>
      </source>
    </sources>
  </configuration>
</plugin>
----

Custom discovery providers are loaded from the Maven plugin classpath, so add them as plugin dependencies:

[source,xml]
----
<plugin>
  <groupId>io.micronaut.jsonschema</groupId>
  <artifactId>micronaut-json-schema-maven-plugin</artifactId>
  <dependencies>
    <dependency>
      <groupId>example.oracle</groupId>
      <artifactId>oracle-schema-providers</artifactId>
      <version>1.0.0</version>
    </dependency>
  </dependencies>
  <configuration>
    <sources>
      <source>
        <name>legacy</name>
        <providerClassName>example.oracle.LegacySchemaDiscoveryProvider</providerClassName>
        <options>
          <tablePattern>LEGACY_%</tablePattern>
        </options>
      </source>
    </sources>
  </configuration>
</plugin>
----

As with Gradle, each custom provider must also be registered in:

[source]
----
META-INF/services/io.micronaut.jsonschema.generator.oracle.OracleSchemaDiscoveryProvider
----

For example:

[source]
----
example.oracle.LegacySchemaDiscoveryProvider
----

The configured `providerClassName` must exactly match the implementation class name listed in that file.

=== Troubleshooting Custom Providers

If a custom provider is not resolved at runtime, check these points first:

* The provider jar is on the plugin classpath.
* Gradle uses `oracleJsonSchemaProviders`.
* Maven uses plugin `<dependencies>`, not regular project dependencies.
* The jar contains `META-INF/services/io.micronaut.jsonschema.generator.oracle.OracleSchemaDiscoveryProvider`.
* The service file lists the exact implementation class name configured through `providerClassName`.
* The provider implementation has a public no-argument constructor.
* If the provider jar is shaded or repackaged, `META-INF/services` entries are merged instead of overwritten.
* The provider and plugin use compatible `micronaut-json-schema` versions.
* Any transitive libraries required by the provider are also visible on the same plugin classpath.

=== Maven credentials

The Maven plugin supports both direct properties and Maven `settings.xml` server lookup.

You can pass connection settings directly on the command line:

[source,bash]
----
mvn generate-sources \
  -DoracleJsonSchema.skip=false \
  -DoracleJsonSchema.jdbcUrl=jdbc:oracle:thin:@localhost:1521/FREEPDB1 \
  -DoracleJsonSchema.username=app \
  -DoracleJsonSchema.password=secret \
  -DoracleJsonSchema.targetPackage=example.oracle.generated
----

For better secret handling, configure a Maven server and pass only `serverId`:

[source,xml]
----
<settings>
  <servers>
    <server>
      <id>oracle-jsonschema</id>
      <username>app</username>
      <password>secret</password>
    </server>
  </servers>
</settings>
----

[source,bash]
----
mvn generate-sources \
  -DoracleJsonSchema.skip=false \
  -DoracleJsonSchema.jdbcUrl=jdbc:oracle:thin:@localhost:1521/FREEPDB1 \
  -DoracleJsonSchema.serverId=oracle-jsonschema \
  -DoracleJsonSchema.targetPackage=example.oracle.generated
----

Credential resolution order is:

* Explicit plugin configuration or `-DoracleJsonSchema.username` / `-DoracleJsonSchema.password`
* `serverId` lookup from Maven `settings.xml`
* Fail the build if credentials are still missing
